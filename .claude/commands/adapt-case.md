Кейс: $ARGUMENTS

Ты адаптируешь конфиг-управляемую заготовку подписочного AI-продукта под этот кейс. Следуй CLAUDE.md.

## Шаг 1. Анализ и 3 идеи (СТОП после этого шага)
1. Выдели из кейса: целевого пользователя, его главную боль, критерии успеха организаторов.
2. Предложи 3 идеи продукта. Для каждой оценку 1–5 и одно предложение обоснования:
   - боль пользователя; вау-фича AI; монетизация (квиз → пейволл → подписка); реализуемость за 12 часов.
   Итоговая таблица + твоя рекомендация.
3. Задай вопрос, какую идею выбрать. Без ответа дальше не иди.

## Шаг 2. Переписать ТОЛЬКО /config (после выбора)
- `config/app.config.ts`: бренд, tagline, лендинг (hero, 3 шага, 3 ценности, статистика, отзывы), параметры `econ`.
- `config/copy/ru.ts` и `en.ts`: только если нужны правки chrome-текстов.
- `config/quiz.config.ts`: 8–10 шагов под боль пользователя (разные типы шагов, последний — loader).
- `config/prompts/analyze.ts`: системный промпт + Zod-схема `AnalyzeResultSchema` под новую ценность. Если схема меняется — обновить компонент `components/result/result-view.tsx` минимально и только в части отображения полей.
- `config/mocks/analyze.ts`: правдоподобные mock-ответы ru и en, проходящие новую схему.
- `config/paywall.config.ts`: тарифы, триал, premium-фичи, тексты вариантов A и B.
- `lib/seed.ts` подстраивается сам по quiz/paywall; проверь, что шаги в воронке осмысленны.
Запрещено: хардкод текстов в компонентах, новые функции вне PLAN.md.

## Шаг 3. Проверка
`npm run config:check` → `npm run lint` → `npm run build` → `npx playwright test` (поправь селекторы теста, если поменялись тексты кнопок). Посмотри экраны квиза, результата и пейволла в браузере на 390px.

## Шаг 4. Коммит
`git commit -m "adapt: <название продукта>"`. В конце выведи: название продукта, что изменено, сколько заняла адаптация.
